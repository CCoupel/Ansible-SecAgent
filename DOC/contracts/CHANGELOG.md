# Changelog des contrats d'interface

## [v3.0.6] — Événements de relais et de routage (hooks) (LOT-3.1 : #225, #245, #265 ; plan : `.claude/workflow/plan-v3.0.6.md`)

- **[ADDED]** `WSS /ws/relay` `event_forward` (#225, #245) — kinds `relay.failover`, `relay.up`, `relay.reconnect`, `relay.down` (sans `hostname`, clé `relay_id`, `relay_chain` origine en premier) ; formes réservées pour `relay.discover`, `relay.rerouted`, `relay.removed`, `relay.converged`, `host.reconnect`, `host.discover`, `host.rerouted`, `host.removed` ; champs additifs `instance_id`, `previous_instance_id`, `cause`, `mode`, `hosts_routed`, `relays_below`, `relays_below_ids`, `reason`, `conn_seq`, `old_chain`, `new_chain`, `relays_connected`, `relays_missing`, `hosts_direct`, `upstream_dropped_events_total`. Détail : `SERVER_SPEC.md` §9.2.
- **[ADDED]** `relay_hello.conn_seq` (pull) et `relay_ack.conn_seq` (push) (#265) — nombre de connexions du process enfant (entier `1..2³¹`, absent/invalide ⇒ 1). Ignoré par un parent v3.0.5.
- **[ADDED]** `WSS /ws/agent` — en-tête `X-SecAgent-Conn-Seq` (#265, entier décimal `1..2³¹`, absent/invalide ⇒ 1), ignoré par un serveur antérieur.
- **[CHANGED]** événement `host.up` (#265) — n'est plus émis aux reconnexions d'un **même process** minion ≥ 3.0.6 : elles donnent `host.reconnect` ; qui veut « toute connexion » s'abonne à `host.up` **et** `host.reconnect`. Minion v3.0.5 (sans en-tête) : inchangé (`host.up`).
- **[CHANGED]** documentation (SERVER_SPEC §9.7) — `relay.updated` ne déclenche aucun hook (propagé seulement) ; la doc affirmait le contraire.
- **[ADDED]** `GET /api/admin/status` (#246) — champs additifs, toujours présents : `upstream_dropped_events` (événements ascendants perdus : file pleine, ou retirés de la file sans pouvoir être envoyés), `upstream_queue_depth`, `upstream_queue_capacity` (`0 / 0 / N` sur une racine sans parent). `secagent-server server status` les affiche. Variables `RELAY_UPSTREAM_QUEUE_SIZE` (défaut 10000, bornes 256..100000) et `RELAY_UPSTREAM_RATE` (défaut 150 événements/s, bornes 10..1000 ; sous le quota 200/s du parent, sans exemption) ; valeur hors borne ⇒ défaut + `[WARN]`. Journal des actions : entrée agrégée `action_type:"upstream_dropped"` (`event:"*"`), une par minute au plus. Le refus de quota d'un `event_forward` n'est plus journalisé par événement mais une fois par minute et par identité.
- **[ADDED]** `WSS /ws/relay` `event_forward` `host.rerouted` / `relay.rerouted` (#244 amendé) — `host.rerouted` : `cause` `moved|direct|indirect` (`reparent` retiré), `old_chain`/`new_chain` descendantes, `old_relay`/`new_relay` (= dernier élément de chaque chaîne) ; `relay.rerouted` : un par relais déplacé entre deux snapshots, avec `hosts_routed`, sans `host.rerouted` par hôte. Hooks : variables `old_relay`/`new_relay` et objet webhook `change {old_relay,new_relay,old_chain,new_chain,cause}`. Additif : un parent v3.0.5 jette ces kinds sans fermer le lien.
- **[ADDED]** `WSS /ws/relay` `event_forward` `relay.converged` (#246) — un seul par promotion, après `relay.failover` : `relays_connected`, `relays_missing`, `hosts_direct`, `hosts_routed`, `upstream_dropped_events_total` ; variable `RELAY_CONVERGENCE_TIMEOUT` (défaut 60 s, bornes 1 s..10 min ; hors borne ⇒ défaut + `[WARN]`). Additif : un parent v3.0.5 jette ce kind sans fermer le lien.
- **[CHANGED]** hooks (#246, T21) — un jeton `{{variable}}` d'une variable **connue** (`event`, `hostname`, `status`, `timestamp`, `enrolled_at`, `relay_chain`, `relay_origin` et les variables d'événement : `cause`, `previous_instance_id`, `old_chain`…) que l'événement ne porte pas est désormais remplacé par une chaîne **vide** (avant : jeton laissé en clair, ex. `previous={{previous_instance_id}}` sur `relay.failover cause=start`) ; un jeton inconnu reste inchangé. S'applique aux actions `file`, `shell` (arguments), `webhook`/`api` (corps, en-têtes).
- Compatibilité : un parent v3.0.5 jette les kinds inconnus (`unsupported event kind`) sans fermer le lien ; monter les parents d'abord (T9).
- Aucun changement BREAKING.

## [v3.0.5] — Durcissement et dettes issues de v3.0.4 (plan validé au GATE 2 ; détail : `_work/reports/planner-plan-v305.md`)

- **[CHANGED]** `WSS /ws/agent` trame `rekey` (#217, LOT-1) — émise aussi périodiquement par le relay pour renouveler le JWT d'agent avant expiration ; format inchangé, rétrocompatible. Nouvelles variables serveur `AGENT_JWT_TTL` (défaut 24h, était 1h codé en dur ; entre 5 min et 7 jours) et `AGENT_JWT_RENEW_INTERVAL` (défaut TTL/3, entre 1 min et TTL/2). Aucune nouvelle route.
- **[ADDED]** `GET /api/admin/link/status` (#234, LOT-3) — champ `state` par relay (`confirmed` | `unconfirmed` | `never_seen`) ; `409 rotation_unconfirmed` : champ additif `never_seen`. **[CHANGED]** `confirmed` vaut `false` pour un relay sans aucun `link_state` (était `true` hors rotation).
- **[ADDED]** `GET /api/admin/link/status` + `POST …/retire-previous` (#215, option C) — `direct` par relay et `not_direct` (relais non connectés en direct depuis la rotation), informatif.
- **[CHANGED]** `WSS /ws/relay` rate limit `event_forward` (#216, LOT-3) — compté par `relay_id` et non plus par lien ; seuil 200/s inchangé.
- **[CHANGED]** `/ws/agent` (#217, M1/M2) — un JWT dont le JTI a été remplacé n'est plus accepté pendant la grâce d'une rotation (même signé avec l'ancien secret) ; seul le JTI immédiatement précédent reste valable jusqu'au premier handshake avec le courant. `POST /api/admin/keys/rotate` : `grace` > `AGENT_JWT_TTL` refusé (`400 grace_exceeds_agent_jwt_ttl`), défaut min(24h, TTL). État : champ optionnel `prev_token_jti` par agent (retour arrière vers v3.0.4 : voir `STATE_SPEC.md`).
- **[CHANGED]** `/ws/agent` (#217, N1) — ping WebSocket du relais toutes les `AGENT_WS_PING_INTERVAL` (30s) et fermeture après 2× sans signe de vie (le minion répond au ping sans changement) ; sonde de la connexion vivante (`AGENT_WS_PROBE_TIMEOUT`, 5s) quand le JWT précédent est présenté : sans réponse il est accepté, avec réponse 401.
- **[CHANGED]** `GET /api/admin/minions/{hostname}` (#233) — `status` superpose la connexion WebSocket vivante (`connected`), comme la liste ; champs inchangés.
- **[CHANGED]** `GET /api/admin/minions/{hostname}` (#233) — champ additif `revoked`. `DELETE /api/admin/minions/{hostname}` : liste noire des JTI (courant et précédent) et drapeau révoqué **avant** la suppression de la ligne, fermeture de la WS **après** (et une seconde fois si une connexion est apparue) ; réponse inchangée.
- Hors contrat d'interface (#214, D2) : `RSA_MASTER_KEY` de moins de 32 octets refusée à `state init` et au démarrage (message avec remède) ; dérivation et fichier d'état **inchangés** (pas de HKDF, pas de `schema_version` 3) : un déploiement à clé courte exécute `state rekey` avant la montée.
- Aucun changement BREAKING.

## [Unreleased] (v3.0.3)

- **[BREAKING]** `GET /api/admin/status` : le champ `nats` est supprimé (NATS retiré, #178). `db`, `ws_connections`, `uptime` et `links` sont inchangés. `secagent-server server status` n'affiche plus la ligne `nats`.
- `GET /api/async_status/{task_id}` supprimé (#176) : jamais alimenté en production ; le statut d'un job async passe par un `exec` de `async_status.py` vers l'agent.
- `POST /api/exec|upload|fetch/{hostname}` : nouveaux refus `503 {"error":"agent_suspended"}` et `503 {"error":"agent_state_unavailable"}` (#173). Inventaire : champ optionnel `secagent_suspended` (#173).
- `/ws/agent` : refus `401` avant l'upgrade d'un token révoqué ou remplacé (#169).
- `GET /api/admin/hooks/log` : lu dans le journal append-only `actions.log` (`RELAY_ACTION_LOG`, défaut `STATE_DIR/actions.log`, rotation 10 Mio × 5) et non plus dans la table `action_log` (#161). `config_snapshot` est désormais **masqué** (secret HMAC, valeurs des en-têtes, corps, arguments shell, query string et userinfo des URL) ; `error` masque les URL. Erreur `500 action_log_not_initialized` si le journal n'est pas configuré.
- `GET /api/admin/hooks/log` (#161b) : les URL de `config_snapshot` et de `error` ne conservent plus que schéma + hôte + port (chemin → `/***`, query → `?***` : le secret des webhooks Slack/Discord/Teams est dans le chemin) ; tout champ d'action inconnu est masqué. Journal existant mais illisible : **`503 {"error":"journal_unavailable"}`** (remplace `500 action_log_error`) ; `[]` seulement si le journal n'existe pas encore ou est vide. Section ajoutée à `REST_ADMIN.md` §5b.
- `GET /api/admin/status` (#183) : nouveaux champs `hooks_queue_depth`, `hooks_queue_capacity`, `hooks_inflight`, `hooks_dropped_events`, `hooks_dropped_actions` (additifs). Journal des actions : entrées agrégées `action_type:"dropped"` (`event:"*"`) quand la file des hooks rejette des événements. Variable `RELAY_HOOKS_QUEUE_SIZE` (défaut 10000).
- `GET /api/admin/tokens` (tokens plugin) : champ `last_used_approximate: true` quand `last_used_at` / `last_used_ip` sont renseignés : ils sont en retard (persistés avec la prochaine écriture du fichier d'état) et peuvent être perdus lors d'un arrêt brutal (#160).
- Les écritures échouent (erreur serveur) tant que l'instance n'est pas le maître confirmé (état en lecture seule, #160/#163).
- `POST /api/admin/relays` (mode push, #165) : nouveau champ **`urls`** (liste d'adresses `wss://` des instances de l'enfant, essayées dans l'ordre, 16 max). `url` (chaîne) reste accepté (= liste d'un élément) ; `url` **et** `urls` ensemble → `400 url_and_urls_are_exclusive`. Une adresse non `wss://`, avec userinfo, dupliquée ou visant loopback / lien-local / métadonnées cloud / `0.0.0.0` / multicast refuse toute la liste (`400 invalid_push_target`, adresse jamais répétée ; RFC1918 accepté). Réponses et `GET /api/admin/relays` : `urls` + `url` (= première adresse, compatibilité). `REPEATER_UPSTREAM_URL` et `RELAY_API_URL` acceptent une liste séparée par des virgules ; `relays add --url a,b`.
- Variable `REPEATER_CA_FILE` (#147) : CA de confiance des liens sortants (pull, push, CLI), remplace les CA système, sans option skip-verify ; fichier inutilisable ⇒ démarrage refusé (CLI : erreur, pas de repli sur les CA système).
- `GET /health` (#163) : champs `role` (`master`) et `instance_id` ajoutés. Nouvelle commande locale `secagent-server status --local` (fichier `RELAY_STATUS_FILE`, sans port ni API). Perte du verrou maître : WebSockets fermées en `1001` (jamais `4001`), code de sortie 75. `RELAY_SINGLE_INSTANCE` supprimée.
- Écriture refusée par une instance en lecture seule (#163) : **`503 {"error":"state_read_only","reason":…}`** à la place du `500 db_error` ; `GET /api/admin/status` : champs additifs `state_mode`, `state_mode_reason`, `role`, `instance_id`, `write_seq`, `beat`, `last_beat_at`. `POST /api/admin/revoke/{hostname}` : si la blacklist ne peut pas être écrite, la réponse est une erreur (503 en lecture seule) et le lien n'est plus fermé en `4001`.
- Contrat NATS (`NATS.md`) obsolète : à retirer par #172.
